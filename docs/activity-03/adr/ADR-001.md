# ADR-001: Separate ESP32 Communication Control from Arduino Real-Time Control

## Status

Accepted

## Context

CareHoMED requires both network communication and real-time control of physical dispensing hardware.

The ESP32 is responsible for communication between the web system and the embedded cabinet, while the Arduino Mega is responsible for real-time hardware operations.

Combining these responsibilities into one controller could make the system more dependent on network communication and reduce the separation between application-level and hardware-level operations.

## Decision

The system will use two controllers with separate responsibilities:

- **ESP32** — communication controller
- **Arduino Mega** — real-time hardware controller

The ESP32 communicates with the web/backend system and sends high-level commands to the Arduino Mega.

The Arduino Mega receives these commands through UART/serial communication and performs the corresponding hardware operations.

## Rationale

This separation provides:

- Clear separation of responsibilities
- More reliable real-time hardware control
- Reduced coupling between the web system and hardware
- Easier independent testing of communication and hardware functions
- Better isolation of hardware-specific implementation details

The Arduino Mega can continue handling real-time operations without depending directly on web or network timing.

## Alternatives Considered

### Alternative 1 — ESP32 Only

The ESP32 could perform both network communication and real-time hardware control.

**Rejected because:**

- Network communication and hardware control would share the same controller.
- Real-time operations could become more dependent on communication tasks.
- Hardware and application responsibilities would be less clearly separated.

### Alternative 2 — Arduino Mega Only

The Arduino Mega could control both the hardware and the system's communication functions.

**Rejected because:**

- It is less suitable for the web/network communication requirements.
- It would combine communication responsibilities with real-time hardware control.

## Consequences

### Positive

- Hardware control remains isolated from network communication.
- The system has clearer component responsibilities.
- Testing can be performed separately for communication and hardware control.
- Hardware-specific implementation remains within the embedded controller.

### Negative

- Requires two microcontrollers.
- Requires additional wiring.
- Requires a defined UART communication protocol.
- Introduces an additional communication boundary that can fail.

## Failure Considerations

If communication between the ESP32 and Arduino Mega fails, new remotely initiated dispensing commands should not proceed until communication is restored.

The Arduino Mega remains responsible for handling the physical hardware safely.
